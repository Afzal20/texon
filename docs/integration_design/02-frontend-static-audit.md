Frontend/Odoo migration priorities:

1. **Baseline and contract:** choose supported pages for the first apparel flow, verify backend routes, document the versioned facade, pin toolchain, retire stale GraphQL instructions.
2. **Identity foundation:** one session model; verified roles/company selection; restricted server-side Odoo connector; no browser Odoo credentials; login, refresh, logout, invalid cookie and access revocation scenarios.
3. **Shared data layer:** typed paginated lists and aggregates; distinct error states; stable identifiers; command endpoint client; operation polling/status; conflict handling; genuine sync health.
4. **First useful workflow:** buyer → approved style/color/size matrix → customer order → BOM/material requirement → receipt of tracked fabric rolls → production → quality hold/release → packing and shipment. Keep broad Odoo administration in Odoo-native views initially.
5. **Focused UI upgrades:** replace numeric IDs, ad hoc status dropdowns, guessed field names and toast-only controls on the selected flow. Wire named permissions and meaningful empty/loading/error states.
6. **Evidence and expansion:** execute the full workflow against real Odoo, including partial receipts, shortages, retries, quality rejection and returns. Expand additional modules only after that path passes.

Acceptance additions specific to these frontend findings:

- Expired or forged cookie cannot load protected data; a stale cookie does not trap the user in a login redirect loop.
- Browser storage contains no Odoo API key and, if the selected facade design is used, no access/refresh JWT.
- Five simultaneous requests during session expiry produce one refresh and preserve one coherent session.
- A denied stock endpoint displays permission failure; an offline connector displays unavailable/stale state; a genuine empty stock result displays zero.
- Fetching page two requests only the bounded required dataset and preserves server filters.
- A buyer PO creates an Odoo sales document; a supplier PO creates a purchase document.
- Clicking “confirm” twice results in one business transition and a visible operation status.
- A rejected/stale transition preserves entered data and explains the actual conflict.
- Quality-held stock cannot be selected for shipment.
- Export creates a downloadable file containing only authorized filtered records.
- Revenue uses the selected period/company/currency; buyer count counts unique buyers.
- “Last synced” reflects acknowledged data refresh, including a visible stale condition after connector downtime.
