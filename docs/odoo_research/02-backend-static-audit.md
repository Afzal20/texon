**What is already implemented and should be retained/reviewed**

- JWT/session authentication and authenticated defaults: `config/settings.py:387–418`; access expiry/refresh rotation/blacklist configured at `:440–449`.
- Dedicated user management with `users.*` RBAC: `authentication/api.py:103–127`.
- User serializer removes privileged staff/superuser flags for non-superusers, forbids non-superuser edits to superusers, protects password changes: `authentication/api.py:57–99`.
- Profile serializer makes privileged flags read-only: `authentication/serializers.py:7–25`.
- Dedicated RBAC writes require `roles.manage`: `rbac/views.py:43–75`; system-role deletion protection at `:48–51`.
- Production secret required when debug false, CORS allowlist and production email-verification default exist. Avoid reporting these already addressed issues as absent.
- However `employee` and `is_verified` remain writable to user editors (`authentication/api.py:42–55`); since department affects finance authorization (`core/permissions.py:16–21`), employee reassignment deserves explicit authorization and regression coverage.
- Public registration is wired at `authentication/urls.py:14`; decide invitation-based ERP onboarding before international demos with real data.
- Read tier is only applied to accounts (`core/api.py:73–75`), while selected generic writes have extra RBAC mapping (`:81–88`). The multiple permission systems need a clear crosswalk to Odoo roles.
